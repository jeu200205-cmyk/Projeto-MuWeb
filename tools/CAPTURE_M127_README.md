# M127 World1 / World11 physical capture

This optional DevTools helper is **read-only**. It records M69 `Scene.loadRealMap` profiles (`mapEntryCaptures`, including teleports), M74 outer initial world-entry profiles (`outerCaptures`) and M75 structured object-stage profiles (`captures`), including M119/M121–M127 diagnostics, whole-session requestAnimationFrame deltas, and PerformanceObserver long tasks (if supported). It does **not** modify any game, renderer, asset, map or scheduler owner. It does not generate artificial benchmark results.

1. On the Windows PC, use only the official MuPromax 1.0.1 Data and a valid running client. Open browser DevTools **before** entering Lorencia/World1, paste `CAPTURE_M127_WORLD1_WORLD11.js` into Console and run it.
2. Enter World1, allow the map to finish staging, remain for at least 10 seconds, then enter World11 and remain for at least 10 seconds. Repeat in a separate run on the unchanged M125 build with matching conditions (camera, player count, cold/warm caches).
3. Run `__MUWEB_MAPS_CAPTURE_M127__.download()` in DevTools, then `__MUWEB_MAPS_CAPTURE_M127__.stop()`. The downloaded JSON contains `mapEntryCaptures` (M69), `outerCaptures` (M74 when the runtime publishes it), `captures` (M75), `disposeCaptures` (M127 old-world reference sweep vs renderer/resource teardown), and frame statistics. **Important:** the current `GameApp._buildWorld` publishes M74 on initial world entry; `GameApp._changeMap` teleports may not publish a new M74 outer snapshot. A missing World11 `outerCaptures` entry after a teleport is not a failed capture of M75. Use `mapEntryCaptures` (M69) and `captures` (M75) for those transitions until a separate non-conflicting M74 transition owner is implemented. If a profile never appears, check the console for `[PERF M75]` and whether the game exposes `__MUWEB_MAP_OBJECT_STAGE_PROFILE__`.

Interpretation: `frameStats` covers the **whole recording session**, not per-world frame attribution. M125 buckets are **await-inclusive wall time**; they do not independently prove a browser main-thread long task. Only a Chrome trace/PerformanceObserver long task can establish synchronous stalls. No GPU timing is implied by the M98/M99 **byte** counters. Compare `rendered`, `missing`, authored ObjectXX counts, terrain/BodyLight and visible effects before claiming parity or FPS improvements.

M127's `disposeCaptures` are produced by the outgoing map layer at transition time; for a World1→World11 transition the disposal record belongs to **World1**. If no old layer was disposed during recording, this array may legitimately be empty. Compare M126 vs M127 under identical conditions to evaluate reference-retirement overhead. The Node synthetic microbenchmark is not a WebGL measurement and does not establish an FPS increase.
